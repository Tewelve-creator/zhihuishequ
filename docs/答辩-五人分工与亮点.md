# 答辩用 · 五人分工与亮点功能（详版）

> 项目：**AI 智慧社区服务助手**（多社区 SaaS）  
> 分工口径（按组内约定）：  
> ① 报修报事　② 活动管理 + 邻里圈　③ 社区商城 + 支付　④ 访客登记 + 物业缴费　⑤ SaaS 管理  
> 其余功能均摊塞入五人，尽量工作量接近。

---

## 一、一页总览

| 成员 | 主责（必讲） | 均摊塞入（其余功能） | ⭐ 建议亮点 |
|------|--------------|----------------------|------------|
| **第一人** | 报修报事 | 分派/分类/统计/反馈、巡检运维、设备维保、网格员移动待办、AI 识图报修对接 | 工单位置可定位 + 网格员 App 现场处置 |
| **第二人** | 活动管理 + 邻里圈 | 失物招领、公告通知、消息中心、敏感词、情绪调解工单展示、邻里互助/举报评论 | 活动报名闭环 + 邻里内容治理 |
| **第三人** | 社区商城 + 支付 | 商户后台、入驻审核、佣金结算、优惠券、业主车辆/车位/临停台账 | 三端商城交易 + 支付履约闭环 |
| **第四人** | 访客登记 + 物业缴费 | 收款催缴通知、缴费流水/欠费/收据、楼栋房屋住户档案、迁入迁出审批、房屋绑定切换 | 访客通行 + 物业费缴付全链路 |
| **第五人** | SaaS 管理 | 多租户登录权限、套餐功能码与降级、AI 智能管家/知识库、数据大屏、物业账号、系统运维配置 | 租户套餐商业化 + AI 管家/驾驶舱 |

## 二、第一人｜报修报事（主）

### 2.1 定位

社区「问题处置」主链路：居民报上来 → 物业派出去 → 网格员办完。  
均摊承接设施侧的巡检、设备维保，以及移动端待办，避免运维能力散落无人认领。

### 2.2 功能清单（含均摊）

| 类型 | 功能 | 端 |
|------|------|-----|
| **主责** | 报修工单、报事工单 | App + 物业后台 |
| **主责** | 报修/报事分派、分类管理、工单统计、意见反馈 | 物业后台 |
| **均摊** | 巡检点位、巡检任务、打卡、隐患、巡检记录 | App + 后台 |
| **均摊** | 设备清单、设备维保与记录 | App + 后台 |
| **均摊** | 物业/网格员工作台、待办（报修/巡检/维保） | App 物业态 |
| **均摊** | AI 识图结果「确认生成报修单」对接（识图能力属第五人） | App |

### 2.3 ⭐ 亮点：工单位置闭环 + 移动现场处置

- 工单绑定房屋位置：`楼栋 / 单元 / 房号 / location_label`（公共设施可不填房号）  
- 物业列表可见位置，便于派单  
- 网格员 App：待办接单 → 现场处理；巡检打卡、维保记录同一套移动入口  

**流程**

```
居民选房屋提交报修/报事（可带图，可接 AI 识图建议）
  → 物业分派网格员
    → App 待办处理 → 完结
      → 统计大屏「工单」指标可引用（大屏页面属第五人）
```

### 2.4 技术要点

- 服务：`community-repair`（报修/巡检/设备）  
- 前端：`app` repair、staff/*；`admin-web` Repair*、Inspection*、Equip*  
- 状态机：待处理 → 处理中 → 已完结  
- 图片：MinIO / 本地兼容  

### 2.5 演示脚本（约 2 分钟）

1. 居民提交带房屋的报修  
2. 物业指出位置列并分派  
3. 网格员 App 待办处理  
4. 可选：巡检任务打卡  

### 2.6 评委问答

| 问 | 答 |
|----|-----|
| 和 AI 谁做什么？ | 第五人提供识图/意图接口；我负责工单落库、分派与状态 |
| 位置数据从哪来？ | 房屋档案由第四人维护；提交时写入工单快照 |

### 2.7 小结口述

> 我负责报修报事，并承接巡检维保与网格员移动待办。亮点是工单能定位到楼栋房屋，并能在手机上现场办结。

## 三、第二人｜活动管理 + 邻里圈（主）

### 3.1 定位

社区「氛围与内容」主链路：有活动可报名、有邻里可交流、有失物可寻、有公告可触达。  
把内容治理（评论/举报/敏感词）和情绪工单展示一并收口，避免运营类功能碎片化。

### 3.2 功能清单（含均摊）

| 类型 | 功能 | 端 |
|------|------|-----|
| **主责** | 活动列表、发布、分类、报名管理、活动统计 | 后台 + App |
| **主责** | 邻里动态发帖/点赞/评论、动态管理 | App + 后台 |
| **均摊** | 评论管理、举报管理、邻里互助 | 后台 |
| **均摊** | 失物招领、认领核实、物品分类（AI 匹配接口接第五人） | App + 后台 |
| **均摊** | 公告通知发布、定时发布、居民公告列表详情 | 后台 + App |
| **均摊** | 消息中心（站内信列表/已读） | App |
| **均摊** | 敏感词库；情绪调解工单的物业侧处理页（识别能力属第五人） | 后台 |

### 3.3 ⭐ 亮点：活动报名闭环 + 邻里内容治理

**活动闭环**

```
物业发布活动（时间/地点/名额）
  → 居民报名（名额校验）
    → 报名管理 / 活动统计
```

**邻里治理**

```
居民发帖互动 → 物业动态/评论管理
  → 举报处理、敏感词过滤
    → 情绪倾诉入口产生预警工单（识别第五人，工单列表我侧展示处理）
```

失物招领与公告、消息中心同属「社区内容与触达」，一并归本组，答辩时强调**运营内容一条线**。

### 3.4 技术要点

- 活动/邻里/失物/公告：多在 `community-repair` 业务域  
- 前端：`app` activity、appeal/neighbor、lost、notice、message；`admin-web` Activity*、Moment*、Lost*、Notice*、AiEmotion*、AiSensitive*  
- 与第五人：情绪识别、失物匹配出接口；我做产品页与人工核实/处理  

### 3.5 演示脚本（约 2 分钟）

1. 后台发布/展示活动 → 居民报名  
2. 居民发一条邻里动态 → 后台动态管理  
3. 可选：失物一条 / 公告一条 / 情绪工单列表  

### 3.6 评委问答

| 问 | 答 |
|----|-----|
| 活动和邻里有何区别？ | 活动是官方组织、有名额报名；邻里是 UGC 社区互动 |
| 内容安全怎么做？ | 敏感词 + 举报处置；严重情绪走预警工单 |

### 3.7 小结口述

> 我负责活动管理和邻里圈，并承接失物、公告、消息与内容治理。亮点是活动报名闭环，以及邻里内容可管可控。

## 四、第三人｜社区商城 + 支付（主）

### 4.1 定位

社区「交易」主链路：商品、购物车、下单、**支付**、履约、退款；并带上商户侧与结算。  
车辆/车位作为生活服务配套均摊进来（与商城同属便民经营板块），工作量与另外四人拉齐。

> 说明：本组「支付」指**商城订单支付与资金流**；物业费支付在第四人。两边支付状态语言尽量对齐（待支付/支付中/已支付/失败）。

### 4.2 功能清单（含均摊）

| 类型 | 功能 | 端 |
|------|------|-----|
| **主责** | 商品/分类/上下架/库存/价格/图片 | 商户后台 |
| **主责** | 逛店、购物车、结算、**支付**、支付结果、我的订单 | 居民 App |
| **主责** | 接单、配送/自提、完成、退款；超时关单与库存回滚 | 商户端 |
| **均摊** | 独立商户后台（店铺/订单/优惠券/营销资金） | 商户端 |
| **均摊** | 物业：商户列表、商超总订单、入驻初审、佣金应收 | 物业后台 |
| **均摊** | 业主车辆、车位档案、临时通行记录、停车收费台账 | 后台 + App |

### 4.3 ⭐ 亮点：三端商城交易 + 支付履约闭环

```
商户上架 → 居民加购下单并支付
  → 商户履约（配送/自提）
    → 物业看订单与佣金应收
```

业务细节可讲：起送价、配送方式、未支付关单回滚库存、店铺 `shop_id` 隔离、演示支付/预留微信支付宝。

### 4.4 技术要点

- `app/pages/mall/*`；商户 `/merchant/*`；物业 Mall/Store*  
- 订单状态机 + 支付单幂等  
- 租户 + 店铺双隔离  

### 4.5 演示脚本（约 2 分钟）

1. 商户上架或指出商品  
2. 居民下单并走支付结果页  
3. 商户/物业查看订单  
4. 可选：车辆登记一笔  

### 4.6 评委问答

| 问 | 答 |
|----|-----|
| 和第四人物业缴费支付有何不同？ | 单据不同：我是商城订单；他是物业费账单。状态口径对齐，业务分离 |
| 库存如何防超卖？ | 下单扣减，取消/超时回滚，条件更新库存 |

### 4.7 小结口述

> 我负责社区商城与订单支付，并承接商户结算和车辆便民能力。亮点是商户、居民、物业三端跑通一笔带支付的交易。

## 五、第四人｜访客登记 + 物业缴费（主）

### 5.1 定位

社区「通行与物业费」主链路：谁来访、怎么通行；物业费怎么开、怎么缴、怎么催。  
房屋/住户/迁入迁出是缴费与访客的数据根基，均摊由本组维护，保证「人—房—费—访」一致。

### 5.2 功能清单（含均摊）

| 类型 | 功能 | 端 |
|------|------|-----|
| **主责** | 访客预约、通行码/分享、预约列表、物业访客审核管理 | App + 后台 |
| **主责** | 物业费账单、居民待缴/确认支付/结果、电子收据、缴费记录 | 后台 + App |
| **均摊** | 缴费流水、欠费汇总、收款/催缴通知 | 物业后台 |
| **均摊** | 楼栋信息、房屋档案、业主住户、租客管理 | 物业后台 |
| **均摊** | 居民房屋绑定、多套房切换当前房屋 | 居民 App |
| **均摊** | 迁入迁出申请、审批、历史、统计 | 后台 + App |

### 5.3 ⭐ 亮点：访客通行 + 物业费缴付全链路

**访客**

```
住户发起访客预约 → 物业审核 → 访客凭通行信息到访
```

**物业费**

```
物业开账单（关联房屋）→ 居民支付 → 收据/流水
  → 未缴进欠费汇总 → 催缴通知
```

**房屋主数据**  
多套房切换后，缴费与访客都挂在「当前房屋」上，和第一人报修位置同源。

### 5.4 技术要点

- 访客、缴费：`community-repair`；房屋绑定：`community-auth`（House*）  
- `app` visitor、payment、house；`admin-web` Visit*、Fee*、House*、Residents*、Move*  
- 账单状态：待缴 / 支付中 / 已缴 / 失败；支付幂等  

### 5.5 演示脚本（约 2 分钟）

1. 居民切换/绑定房屋  
2. 发起访客预约 → 物业审核  
3. 物业开账单 → 居民缴费看收据  
4. 可选：欠费汇总或迁入迁出审批  

### 5.6 评委问答

| 问 | 答 |
|----|-----|
| 为何房屋档案归你？ | 缴费按户、访客按户，人房数据是我主责的上游 |
| 和商城支付如何分工？ | 我负责物业费账单支付；商城订单支付归第三人 |

### 5.7 小结口述

> 我负责访客登记和物业缴费，并维护房屋住户与迁入迁出。亮点是访客通行可管，以及物业费从开单到收据、欠费催缴的完整链路。

## 六、第五人｜SaaS 管理（主）

### 6.1 定位

平台「商业化与智能底座」：租户开得了、套餐卖得动、权限控得住、到期降得级；并承接 AI 管家与数据大屏，作为全组差异化展示面。

### 6.2 功能清单（含均摊）

| 类型 | 功能 | 端 |
|------|------|-----|
| **主责** | 开户向导、SaaS 租户管理 | 运营端 |
| **主责** | 套餐管理、订单、到期预警、租户授权 | 运营端 |
| **主责** | 经营分析、财务管理（退款/对账）、结算（佣金账单/提现/分润规则） | 运营端 |
| **主责** | 平台设置、账号权限、安全审计、系统配置、服务监控 | 运营端 |
| **均摊** | 多端登录注册、角色权限、社区选择、功能码降级（网关） | 全端底座 |
| **均摊** | 物业侧套餐订阅概览/升级/订购记录；物业账号管理 | 物业后台 |
| **均摊** | AI：智能问答、知识库、意图识别、识图服务、情绪识别、失物匹配、额度 | AI 服务 + 配置 |
| **均摊** | 社区运营驾驶舱 / SaaS 驾驶舱（统计接口 + 大屏页） | 物业/运营后台 |
| **均摊** | 运营端商户入驻终审、商户营收监管等平台级能力（与第二/三人业务协同） | 运营端 |

### 6.3 ⭐ 亮点：租户套餐商业化 + AI 管家 / 驾驶舱

**SaaS 商业化**

```
开户 → 配套餐功能码 → 订购/续费
  → 到期预警 → 降级/冻结（仅保留基础能力）
```

**AI 智能管家**  
知识库 RAG 问答；对话意图引导报修（落单交第一人）；Mock/真模型可切换。

**数据大屏**  
左右与底部：**真实**工单/待办/事件数据；中间楼栋态势：Three.js **演示**孪生（答辩时主动说明）。

### 6.4 技术要点

- `community-saas`、`community-auth`、`community-gateway`、`community-ai`、`community-stats`  
- 功能码：`basic_repair`、`ai_chat`、`data_dashboard` 等  
- 租户上下文 + SQL 隔离  

### 6.5 演示脚本（约 2.5 分钟）

1. 运营端：租户 + 套餐授权  
2. 说明降级策略（可提 degraded 演示思路）  
3. AI 管家问答一条  
4. 打开物业数据大屏：真实指标 + 孪生演示定位  

### 6.6 评委问答

| 问 | 答 |
|----|-----|
| SaaS 核心是什么？ | 多租户隔离 + 套餐功能码商业化 + 到期治理 |
| 大屏数据真假？ | 指标与事件真；中间孪生是可视化演示场景 |
| AI 如何协作？ | 我出能力与接口；报修落单、邻里/失物展示由对应主责承接 |

### 6.7 小结口述

> 我负责 SaaS 管理，并承接登录权限、AI 管家与数据大屏。亮点是租户套餐可售可降级，以及智能问答与运营驾驶舱。

> 我们按五条业务线分工：  
> 第一人报修报事，兼巡检维保与移动待办；
